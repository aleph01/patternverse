Publication and age assumptions

R7 is already complete: its input cutoff is 07:00 and publication is 07:20. R8 has input cutoff 08:00 and a fixed scheduled finish at 08:20, including its checks. Before that finish it is processing. Afterward, only exact coverage of A, B, C and D activates R8. The active-reference switch is atomic in this in-memory simulation (each reader sees one complete set), with no propagation delay; these are declared application policies, not cloud-service defaults.

Input-cutoff age = lookup time minus the active run's cutoff. An age of at most 120 minutes is accepted, including equality. Missing rows are reported as missing even when the active run is old. Existing stale values remain inspectable but are not returned as usable predictions. No fallback is silently substituted.

Candidate predictions are computed immediately for explanation, including before their simulated publication time. They remain separate from the active consumer view. No clocks run automatically, no database is modified, and no actual job, file I/O, retry, storage consistency, runtime benchmark, model training or forecast-quality experiment is executed. Input-cutoff age does not describe every event's age or guarantee freshness within the source snapshot.
