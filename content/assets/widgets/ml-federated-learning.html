Assumptions and exact rules

The model is the scalar prediction w × x, with no intercept. Client A holds (1,0), (1,1), (1,1), (1,2); B holds (x,3), (x,5), where x is the feature control; C holds (1,−1), (1,−1). All records are invented and fixed. The local loss is mean half-squared error. Each local step averages x × (w × x − y) over that client's records and subtracts 0.10 times that gradient.

Every participating client receives exactly the same starting w for its round. A participant performs the selected number of local full-batch steps, and all return synchronously. Example weighting uses n_client / n_returned; client weighting uses 1 / returned_clients. These correspond to distinct objectives. The fixed participating subset is reused for every attempt; excluded clients do no local training and send no update. No returned updates means retain w and skip the round.

The two centralized references perform one global gradient step for each local step in a completed round, starting at zero. One reference uses only the participating clients; the other uses all three. Both use the chosen objective. With no completed rounds the full-population reference stays at zero; the participating reference is undefined when no clients participate. These are counterfactual calculations available because the page contains every invented record; they do not give a real coordinator access to client records. Differences can arise from multiple local steps or a changed participant population; they are not automatically attributable to just one cause.

Losses are training objectives, not validation or test scores. Example weighting averages every record equally; client weighting averages each client's mean loss equally. The client-loss table always reports each client's own mean half-squared error so local regressions remain visible. This is a teaching inspection, not an implemented private evaluation protocol.

The payload count is logical scalar parameter values: one download and one upload per participating client per completed round. Counts, configuration, evaluation, transport, secure-aggregation messages, retransmissions, and serialization are excluded. It is not a byte or latency estimate. Local example passes count records processed by full-batch gradient steps, not distinct new examples.

Clients and record counts are honest; schema, model version, feature meaning, and coordinate system agree. No minibatch randomness, client sampling probabilities, device scheduling, late updates, compression, poisoning, clipping, secure aggregation, or differential privacy is simulated. The page deliberately displays records, local models, and gradients for explanation. Keeping records local in an actual deployment does not make updates private.
