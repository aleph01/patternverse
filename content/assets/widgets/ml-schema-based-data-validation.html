      Assumptions and scope
      

        This small validator implements only the declared required fields, scalar types, inclusive
        bounds, allowed categories, and no-extra-field policy. It is original teaching code, not a
        JSON Schema engine or TensorFlow Data Validation. IDs are display metadata outside the
        feature object. Type failure stops further checks for that field, so null is one type
        violation, not several range violations.
      

      

        Strict mode never coerces data. Explicit conversion accepts finite signed decimal strings in
        distance_km only, preserves raw values, and lists every conversion; it does not repair any
        other field. No rows are silently removed. Every violation holds the whole batch; passing
        rows are not automatically released.
      

      

        The metres scenario supplies six otherwise conforming numeric values but no unit metadata.
        The validator cannot infer their physical units. A passing batch is eligible under these
        checks, not certified meaningful, representative, leakage-free, or ready for every model.
        Allowing a new category does not update the downstream encoder or model.
