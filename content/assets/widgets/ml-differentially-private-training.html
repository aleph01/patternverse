Privacy ledger: randomized mechanism

Four public slots; replace one record; full-batch access (q = 1). Each clipped contribution has norm at most C, so sum sensitivity is 2C. Each access adds fresh, independent Gaussian noise with SD σC per coordinate. Initial parameters and settings are public. Only covered noisy outputs are released.

Assumptions and limits of the calculation

The ledger computes ρ = T × (2C)² / (2(σC)²) = 2T/σ² and ε = ρ + 2√(ρ ln(1/δ)). This is the Gaussian zCDP bound composed across accesses and converted to approximate DP, not the tightest possible ε. Natural logarithms are used. With σ = 0 this general mechanism has no finite DP bound for the chosen δ.

T changes the accounting only: the diagram shows the first update, not T training updates. Later accesses must satisfy the same sensitivity bound conditional on earlier noisy states. No sampling amplification, private model selection, or user-level guarantee is included. Settings are not chosen from private data.

Replay z values are fixed public examples, not sampled noise. Even the zero replay has the same theoretical ledger when σ is unchanged; a single displayed noise value does not determine a mechanism's guarantee. A production mechanism needs fresh independent, appropriately generated Gaussian randomness and must not release raw gradients or reveal its noise. This page is not a private training tool.

Reference: Bun and Steinke, Propositions 1.3 and 1.6, Lemma 2.3, and multivariate Lemma 2.5. This replay does not simulate a data distribution or measure model accuracy.
