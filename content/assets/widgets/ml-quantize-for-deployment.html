        The custom record stores six signed weight codes, then little-endian FP32 weight scales, two
        FP32 biases, and one FP32 input scale, without alignment padding. Two 4-bit codes share a
        byte, low nibble first; 8-bit codes occupy a byte each. Fixed zero points are implicit.
        Shape, bit widths, and layout are provided out of band, not stored in this record. The FP32
        comparison stores only six weights and two biases (32 bytes).
      

      

        This is a teaching format, not a valid LiteRT or ONNX model file. Graph metadata, headers,
        runtime buffers, activation storage, and allocator overhead are excluded. Parameter bytes
        cannot predict peak memory or latency.

        Weights are A = (0.12,−0.08,0.04), B = (2,−1.5,0.5), with biases 0.05 and −0.4. Original
        weights, biases, and fixture inputs are stored as FP32. Max-absolute weights determine
        scales; per-output scales divide each row's maximum by 7 or 127, while the shared scale
        divides the tensor maximum. Signed codes use symmetric ranges −7…7 or −127…127, leaving the
        most negative bit pattern unused.
      

      

        Calibration values are nonnegative and real zero must map to code zero. The input scale is
        the fixture maximum divided by 15 or 255. No evaluation input chooses a scale. Round the
        quotient to nearest, ties to even; then add the zero point and clamp. Clipping counts cases
        where the rounded code exceeds the allowed range. All model zero points are zero.
      

      

        Scales and biases are written to FP32 and read back before quantizing or computing outputs.
        Integer codes are packed and decoded before use. Sums fit signed 32-bit integers here (the
        general three-term bound is 3 × 127 × 255 = 97,155). The browser accumulates exact small
        integers and performs divisions, float comparisons, and output rescaling in JavaScript
        binary64 arithmetic. It does not emulate native FP32 kernels, bias quantization, or output
        requantization.
      

      

        The local number line shows the first A weight on five neighboring codes. Aggregate
