Agentic Coding connects software requirements and evidence to the changes agents produce. The field guide follows work through specifications, bounded tasks, version control, review, integration, and operation.

Begin with [[agentic-specify-the-work|Specify the Work]]. Its first article, [[agentic-specify-outcomes-with-examples|Specify Outcomes with Examples]], makes intended behavior concrete without deciding every implementation detail.

[[agentic-make-boundaries-and-decisions-explicit|Make Boundaries and Decisions Explicit]] makes the permitted scope, required continuity, and unresolved decisions visible before implementation expands.

[[agentic-agree-on-done|Agree on Done]] distinguishes an agent’s stopping condition from completed product work and release, keeping evidence and remaining obligations visible.

Continue with [[agentic-prepare-the-context|Prepare the Context]]. Its first article, [[agentic-ground-work-in-the-existing-system|Ground Work in the Existing System]], replaces repository assumptions with a targeted map of inspected behavior, dependency contracts, and operating conditions.

[[agentic-keep-context-durable-and-discoverable|Keep Context Durable and Discoverable]] keeps those findings and decisions available across sessions without turning every prompt into a project archive.

[[agentic-delegate-and-coordinate|Delegate and Coordinate]] begins with [[agentic-bound-the-task|Bound the Task]], which connects a delegated outcome to authority, resources, decision triggers, and a verifiable handoff.

[[agentic-deliver-small-reviewable-changes|Deliver Small, Reviewable Changes]] organizes agent output into coherent review units while preserving acceptance requirements and integration dependencies.

[[agentic-coordinate-concurrent-work|Coordinate Concurrent Work]] makes edit boundaries, shared semantics, and integration responsibility explicit when implementation proceeds in parallel.

[[agentic-steer-and-recover|Steer and Recover]] begins with [[agentic-steer-through-evidence|Steer Through Evidence]], which uses representative probes and discriminating observations to change direction before uncertain implementation grows.

[[agentic-keep-work-recoverable|Keep Work Recoverable]] preserves both an owned recovery boundary and the observations needed to abandon a failed approach without repeating it.

[[agentic-verify-and-review|Verify and Review]] begins with [[agentic-establish-independent-checks|Establish Independent Checks]], which grounds expected results in defensible requirements and references so tests can challenge the implementation.

[[agentic-verify-the-complete-behavior|Verify the Complete Behavior]] connects component evidence to the assembled path, resulting persistent state, and explicitly specified rejection or interruption behavior.

[[agentic-review-intent-and-risk|Review Intent and Risk]] concentrates review reasoning on consequential assumptions and paths while keeping the whole change accounted for and validating critique.

[[agentic-integrate-and-operate|Integrate and Operate]] begins with [[agentic-keep-a-traceable-change-history|Keep a Traceable Change History]], which connects purpose, coherent changes, decisions, and evidence to the versions reviewed, integrated, and released.

[[agentic-integrate-frequently|Integrate Frequently]] exposes semantic disagreements by combining independent changes promptly and checking the resulting version, while keeping integration and release separate.

[[agentic-release-with-observation-and-recovery|Release with Observation and Recovery]] connects controlled exposure to evidence, compatible transitions, and recovery for both application code and persistent effects.

[[agentic-maintain-and-improve|Maintain Understanding and Improve the Workflow]] begins with [[agentic-make-changes-understandable|Make Changes Understandable]], which connects explanations to inspectable responsibilities, concrete traces, and evidence for normal and failure behavior.

[[agentic-improve-the-flow-of-accepted-work|Improve the Flow of Accepted Work]] closes the field guide by using queues, unfinished-item age, and recurring rework to test improvements in the path to accepted, integrated outcomes.

This is a draft reading edition with eighteen articles across seven populated collections.
