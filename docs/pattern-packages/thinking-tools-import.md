# Thinking Tools Field Guide

Implemented 25 distinct articles and 25 participant-led Pattern Language practices. Conceptual articles contain 834–932 words before references and the executable practice. All content is independently written with original examples and intellectual attribution. The coverage checklist is Untools; its prose, example scenarios, templates, and visual identity are not imported.

The canonical package metadata is [thinking-tools.json](thinking-tools.json). It contains every conventional name, title, ID, primary and secondary verse, collection, creator/source, consulted links, overlap decision, practice interface, result expression, collection bounds, visual decision, and eight specific natural-language recommendation queries per method (200 total). Recommendation queries follow the existing package-sidecar convention; this task does not add a new recommendation service or new frontmatter fields.

Second-order reasoning concerns action consequences; the existing Follow the Consequences concerns beliefs and rules in use. Laddering explicitly returns from purpose through alternative means. Inference traces selected observations into action and back into attention. The conflict diagram adds the objective–needs–proposals structure while allowing a genuine disagreement to remain. Inversion derives negative requirements before a plan exists; the existing premortem specializes in a plan imagined to have failed. Concept mapping emphasizes labeled propositions, while Reconstruct the Map emphasizes retrieval. The related links in the articles connect these methods to existing framing, options, comparison, and experiment practices.

## Practices and outputs

Every practice is implemented in the article’s single `patternverse-language` block, uses `:language 1`, and declares `:output result`. `result` is an inferred, compiler-checked record; numbers remain numbers, choices retain semantic IDs, repeatable entries remain typed records, and ranking preserves whole records. The exact result expression is recorded in the package metadata.

Related fields are submitted together in `!form`, including each repeatable collection entry. `-> yield entry` preserves the form’s record shape in the collection. Later forms reference only accepted prior answers. Rejected required text, out-of-range numbers, or unknown semantic choices leave the submitted form pending. No separate engine, AI call, external action, message delivery, or scheduling is introduced.

The weighted comparison deliberately implements two options and three criteria, with one alternative weighting. Zwicky Box deliberately implements three dimensions, two alternatives per dimension, and three participant-constructed combinations. Issue Trees records two investigation levels. Open collections have modest stated bounds, recorded in the metadata; these are focused first passes rather than exhaustive analysis tools. Names in relationships and parent references are entered manually and checked in the review.

OODA includes optional fields for comparing a real prior prediction with an actual outcome. Starting a new cycle can leave them blank. The practice does not wait for observations or schedule a return. Relationships are structured statements, not automatically established causes. Cynefin asks for evidence and a provisional approach; it never calculates a domain from ratings.

## Visual decisions

Eleven original, accessible native SVG files support twelve articles; the two feedback articles share an explanatory comparison. Each includes a title, description, theme-aware colors, and visible labels. Existing article figure rendering supplies a keyboard-focusable horizontal scroll region on narrow screens. Every article has an explicit visual decision and rationale in the package metadata.

The Impact–Effort practice renders the participant’s own numeric map and full record list. The existing renderer hides numeric/graph drawings below 600px and retains the complete record list; static article diagrams instead remain in a contained scroll region. Restoring a compact interactive map on mobile would be a renderer enhancement, not a missing language capability. Other practices use existing grouped, plain, or ranked compositional displays where useful. Static graphics are explanatory figures, not claims of editable graph functionality. Cynefin deliberately has no Cartesian quadrant illustration or diagnostic chart.

## Remaining implementation gaps, in practical order

The current implementation already supports typed local records and lists, functional transformations, bounded collection entry, whole-record ranking, scalar and multi-choice selection, mixed grouped forms, branching, child calls, replay, and compositional displays. None is declared missing merely because an initial worksheet uses a simpler interface.

| Priority | Layer                                   | Precise limitation                                                                                                                                                                                                  | Present workaround and useful next improvement                                                                                                                                                                                                                                       |
| -------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1        | Language/type contract plus interaction | `!rank [from=records, label=name]` preserves whole records, but single/multiple `!choose` sources accept choice catalogues rather than arbitrary records with a validated stable reference.                         | Rank whole initiatives/options where appropriate. Relationship endpoints and parent names are currently copied manually. Add an explicit record-reference choice contract, stable semantic IDs, source membership validation, and renderer support before replacing those fields.    |
| 2        | Public input/interface                  | Local records, inferred record outputs, and child outputs exist. Public `:input` type declarations currently support scalar/choice types and recursively typed lists; they do not declare arbitrary record schemas. | Each practice starts independently and exports a checked result. A richer handoff needs structural record input declarations, compatibility validation, and authored input interfaces. A typed result alone does not provide automatic cross-practice transfer.                      |
| 3        | Runtime/interaction and host            | Existing step editing uses validated rewind/replay. There is no dedicated transaction to insert, delete, reorder, or revise several accepted collection records as a batch while preserving downstream consistency. | Revisit accepted steps using the existing host; enter a bounded first pass and record revisions in review fields. A collection editor would need explicit stable IDs, invalidation/replay rules, and atomic commit semantics. Basic step editing is not missing.                     |
| 4        | Renderer plus interaction contract      | There is no editable multi-record grid with row/column validation and one confirmed receipt.                                                                                                                        | Decision Matrix uses grouped weight and score forms and real arithmetic; impact estimates use one mixed form per initiative. | 7        | Content interfaces and convenience      | The package declares results, but does not declare semantic shared schemas or automatically prefill another practice. There is no live external review scheduler introduced here.                                   | Keep results and review with actual observations.
