GoF Design Patterns

23 recurring designs for objects and their collaborations.

Explore the problem each design addresses, how it works, and the costs it introduces. The patterns are listed alphabetically. Each article connects to nearby designs to help you compare the choices.

  • Abstract Factory

    Create families of compatible products through one coherent creation interface.

  • Adapter

    Translate an existing interface into the contract a client expects.

  • Bridge

    Separate an abstraction from its implementation so two dimensions can vary independently.

  • Builder

    Separate staged construction of a complex result from the result itself.

  • Chain of Responsibility

    Let a request pass through candidate handlers without coupling its sender to a specific receiver.

  • Command

    Represent an operation as an object or value so it can be stored, scheduled, or composed.

  • Composite

    Give individual objects and groups a common interface for recursive tree operations.

  • Decorator

    Compose optional responsibilities by wrapping an object behind the same contract.

  • Facade

    Offer a focused interface over a subsystem with several collaborating components.

  • Factory Method

    Let a reusable workflow delegate object creation to an overridable method.

  • Flyweight

    Share reusable intrinsic state while keeping context-specific state outside the shared object.

  • Interpreter

    Model a small language through expression objects that evaluate its grammar.

  • Iterator

    Traverse elements through a common protocol without exposing a collection’s representation.

  • Mediator

    Place collaboration rules in a coordinator instead of spreading them across peer objects.

  • Memento

    Capture restorable state without requiring the caretaker to inspect its internal representation.

  • Observer

    Let subscribers receive notifications when a subject changes without hard-coding its dependents.

  • Prototype

    Create a new object by copying an existing configured representative.

  • Proxy

    Stand in for another object to mediate access while preserving its useful interface.

  • Singleton

    Restrict a class to one instance within a defined scope and expose shared access to it.

  • State

    Move state-dependent behavior into explicit state objects and delegate through the current state.

  • Strategy

    Make a varying algorithm or policy explicit and replaceable behind a common contract.

  • Template Method

    Define a stable algorithm skeleton and allow subclasses to customize selected steps.

  • Visitor

    Organize operations separately from a stable family of element types using type-specific dispatch.
