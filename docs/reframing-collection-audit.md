# Reframing collection — repository assessment

Patternverse has two related representations. A public pattern is a Markdown article with strict YAML metadata in `content/patterns`; collections are ordered Markdown entities in `content/collections`. An executable Pattern Markdown source lives in a `.pattern.md` file and is parsed, type-checked, and run by the Rust `pattern-core` compiler/runtime. The current authored language is `:language 1`. The host builds exact, pinned source bundles; `!use namespace.name` resolves a child from that bundle before a run starts. Child calls pass declared typed inputs and export declared outputs. Missing dependencies and cycles fail compilation.

The language supports immutable values, typed text/number/boolean/choice/list/record data, `!ask`, `!choose`, multi-select and ranking, `!show`, `!agent` with bounded return contracts, `~` wording, closed semantic classifiers (`?~`), `?branch`/`?match`, `!collect`, `?loop[max]`, and replay-safe traces. It does not support dynamic invocation of an arbitrary pattern name. Selective orchestration can instead use an authored classifier and forward branches over explicit `!use` calls. No new language syntax is needed for this collection.

At the start of this work, the public entity schema had `id`, `title`, `summary`, `status`, `aliases`, `verses`, and `attribution`, but not tags, a structured source citation, or a semantic version. The source manifest identifies the Commons; executable revisions are content-addressed. The implementation adds tags to the common entity schema and search index. Article attribution and a brief source note convey provenance, while `packages/reframing-patterns/catalog.json` records the adaptation version and structured source metadata without inventing reframing-only frontmatter.

Articles render in the existing entity page; collection membership and order already render through the shared Collection UI. Search indexes title, aliases, summary, body, verse and collection names. Executable source can be included in article Markdown under the existing section that public reading omits. The source remains inspectable and forkable in the Pattern Library/editor where supported. Core tests use Rust compilation and fixture/scenario replay; web tests cover catalog availability and browser flows.

At audit time, the browser standalone runner handled participant interactions and `language.realize`, but not `agent.generate` or `semantic.classify`. Those were host-adapter omissions, not language limitations. The implementation adds a generic contract-aware adapter for those existing effect kinds. It uses the selected local model on desktop and selected ZDR OpenRouter route on web, preserves the pinned effect/receipt boundary, and never silently changes providers.

The collection uses small operator patterns with typed text outputs. Short agent-generated candidate lists are represented as the existing `choices` type; participant selection remains `!choose`, not an AI decision. The main workflow routes to a small subset of explicitly imported operators, returns to a testable frame, and ends without requiring the entire tree. Model-generated causal or motive claims are hypotheses for review, not established findings.
