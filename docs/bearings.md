# Bearings

Bearings lives at `/apps/bearings` and opens the same private situations shown in My Workspace. The home page also includes an app tile.

Each situation in My Workspace has a notebook icon that opens its Bearings notebook directly. The context editor also offers **Open in Bearings**, saving unfinished context edits before the handoff. These links use a situation ID; no context or notebook answers are put in the URL. Local previews on a different origin have separate browser storage; use the existing workspace backup and restore flow to move data between them.

Create or open a situation to work in its notebook. Write directly in cells: use **Start writing** in an empty notebook, or hover between cells to reveal the plus and insert one at that position. Insertion buttons also appear on keyboard focus and remain visible on touch devices; an empty notebook keeps its initial writing button visible. Text saves as you type. Text cells offer three adjacent icon buttons for **Note**, **Comment**, and **Own approach**, with the selected type highlighted. These sit on the cell edge and appear on focus or hover, leaving the writing area free. Switching type keeps the text and caret position. Notes use a clean white surface and fine border; comments use a soft lilac surface with a double left rule; own approaches use mint with a solid green edge. These styles carry into Tree previews, writing, and fullscreen. On desktop, text cells omit their rectangular borders and focus frames; a lighter green line on the left identifies the selected writing and follows its visible text height, including wrapping. Empty notes have no “Write here” placeholder. Desktop writing defaults to a 1 px vertical cursor; shape, thickness, and color can be changed in Settings. Selection and text composition retain the normal editor behavior. Thin horizontal rules separate neighboring cells. Touch layouts retain their existing cell outlines. The existing saved kinds remain compatible: `answer` is displayed as Note and `note` as Comment. **Shift Enter** (or Ctrl/⌘ Enter) inserts and focuses a new cell immediately below it; plain Enter adds a line break. Typing `---` on a line of its own and pressing Enter creates a new cell below, carrying any text after the divider into it. The new cell keeps the same type and sibling level; existing child notes stay with the original cell. Fenced and indented code retain literal dividers. The collapsible library provides searchable patterns and rating scales. Click a pattern’s title or summary to preview its full text in the existing split reader or overlay, without adding a cell or leaving the notebook. Enter or Space on the pattern card also opens the preview; closing it returns focus to that card. The separate plus button still adds the pattern, and dragging still copies it into the notebook or Tree. Add buttons appear on hover or keyboard focus; touch devices keep them available. Drag the whole library card to copy it into the notebook at an insertion point or beside an existing cell. Dropping directly onto an empty text cell replaces that placeholder in place, keeping its position and child notes. Whitespace-only text counts as empty; written titles, prompts, and existing widgets are preserved. Drops between cells still insert a new cell. Each copy has its own state. Ratings are independent slider cells and begin unanswered. There is no fixed bottom text bar.

Text cells use live Markdown editing in place. Type `# ` for a heading, `**bold**`, `*italic*`, backticks for inline code, `- ` or `1. ` for a list, `> ` for a quote, or `[label](https://example.com)` for a link. A triple-backtick fence followed by Enter starts a code block. Pasted Markdown also keeps headings, emphasis, lists, links, fenced code, and tables. Formatting stays visible while writing, with no source/preview switch or extra toolbar. Notebook, Tree, and fullscreen share the same Markdown saved in the cell. Markdown line breaks within code stay literal; outside code, `---` followed by Enter keeps its existing cell-splitting behavior. The visual editor retains Vim motions and editing, Shift Tab type cycling, cursor preferences, inline `@` pattern lookup, cell deletion/undo, and drag-and-drop.

The notebook uses one compact toolbar for the Bearings brand, library toggle, editable title, icon-only Tree/Notebook switch, compact Vim mode indicator, a map button, chapter control, follow pin, and save indicator. The header is a single 58 px row on desktop; no second editor toolbar is shown. Click the bear icon to return to situations; pending edits are saved first. The notebook begins directly below it. Bearings shares Mira’s sans-serif typography, white surfaces, crisp dividers, and Patternverse mint accents. Existing situation context is preserved and remains editable in My Workspace. **Notebook actions** contains keyboard shortcuts, Settings, the downloadable copy, and the Patternverse link; below 900 px it also contains the map button, chapter creation and selection, and the follow toggle. View switching and the editable title stay in the header.

Set an optional **Priority** from 1 to 5 in the situations list or map inspector; **5 is highest**. Existing and new situations begin unassigned. The list's **Priority: highest first** sort puts unassigned situations last and uses recent activity to break ties. Sorting is remembered on this device and does not rearrange the map. Use a list row's visible actions menu to **Rename situation**, or the pencil beside a selected map situation's title. Renaming preserves its notebook and connections.

The library toggle sits on the left. Press **/** to open or close it when you are outside a text field; typing, open pickers, and the overlay reader keep their normal keyboard behavior. Closing from inside the sidebar returns focus to the toolbar. Search stays at the top while the library content scrolls below it. The **With practice** switch below search restricts the pattern list to items with an attached, runnable practice. It combines with search, verse, and collection filters, updates the pattern count, and stays selected when the sidebar closes and reopens. Rating scales remain available. Ratings are tucked into an expandable section and open automatically for a matching search. Click its verse control to open the shared area-based Verse picker, then choose a verse. Browse collection cards in the horizontal carousel below it, using a swipe, trackpad, scrollbar, or the previous/next arrows. **View all** opens a searchable grid of the selected verse's collections. Click a collection to select it, or type its name and press Enter to choose the first match; the picker closes and brings that card into view in the carousel. This quick selection clears the pattern search so the collection's patterns are visible. Collection choices follow the selected verse, and counts show how many patterns are available. **All collections** clears only the collection filter; the reset icon returns to all verses and collections. Collapsing the library retains the selection. Personal collections can include Commons patterns, including nested collections; their relationships resolve through the same compiler as the rest of the workspace.

**Read pattern** opens the full article inside Bearings. When the notebook has enough room, it appears in a right-hand reading pane so you can keep editing beside it; smaller layouts use an overlay. Close or Escape returns focus to where you were working in the notebook. The notebook stays mounted, retaining edits, practice state, and your place. Related-pattern links open in the same reader; other references open separately so the notebook remains available. Articles load on demand with retry after a failed request. Private pattern articles are read and rendered on the device and never fall back to a public pattern with the same ID.

Drag a cell by its left handle, which appears on hover or keyboard focus. With the handle focused, use the arrow keys to reorder. Right-click a cell to delete it, or press **⌘ Delete** (Backspace; Ctrl on Windows/Linux) while writing in it or focusing its handle. This deletes the cell and its child branch, with **Undo** available for about 10 seconds to restore them. Each new deletion starts a fresh 10-second notice. Focus moves to the next remaining cell, or the previous one at the end. Plain Backspace/Delete keeps editing text. Search, title-bar fields, rating inputs, practice forms, and open dialogs keep their own editing keys. Shift F10 opens the same menu from a cell handle. Text fields retain their normal browser editing menus.

On desktop, the notebook shows a slim mini-map along its left edge once at least eight visible cells need scrolling. Each mark represents a cell; the active cell is green and currently visible cells have darker marks. Hover or focus a mark for a text preview, then click or press Enter to jump to that cell. Up/Down and Home/End move between mini-map marks. It updates when cells grow, are removed, or branches or chapters are folded, and stays hidden in Tree view and on narrow or touch layouts.

The book-plus control starts a second chapter and activates chapter navigation. Chapters can be collapsed or selected from the chapter picker. Right-click a chapter heading to merge it with a neighbor. One remaining chapter returns to the continuous notebook. The pin controls following library insertions; the bottom-arrow control opens the final chapter and jumps to the end. Each situation remembers its scroll position and cell edits. Unfinished text from the older bottom bar is preserved as an editable cell when the notebook opens.

## Tree and notebook views

Use **Tree** and **Notebook** above the writing area to switch views of the same saved entries. Tree lays out adjoining columns with horizontal scrolling and no connecting lines or level labels. The selected card stays crisp with a green accent; surrounding cards soften while remaining readable and selectable. Its breadcrumb shows the selected note’s ancestry. Existing entries begin at the top level, without changing their text. Tree cards use one writing area, with no separate note title. Existing headings remain part of that writing and become ordinary body text when edited in Tree. New cards are plain notes in both views.

Click a text card to begin writing immediately. The text area grows with its contents. On hover or keyboard focus, small **+** controls on the top, bottom, and right edges add a note above, below, or as a child. The corner expand icon opens the fullscreen editor. Touch devices expose these controls on the selected card. The library add button inserts a child of the selected Tree note. Dragging a library card onto the top or bottom of a Tree card inserts above or below it; dropping in its center adds a child. Dropping on empty canvas adds a top-level note. A guide marks the destination during the drag. Repeated drops create independent copies. Patterns, ratings, and practices retain their existing controls, including the inline article reader. Confirmed practice responses appear beneath their source pattern. Switching views keeps the selected note and hierarchy; Notebook reads parents before their children and provides a disclosure to fold a branch. Each situation remembers its view, selection, and scroll positions. Reopening or refreshing its URL retains the same notebook.

Tree columns align the parent cards along the open branch on a shared horizontal axis, with an unselected child stack centered against its parent. Siblings form one adjoining stack with rounded outer corners; parent/child joins use inward or outward curves according to their actual heights, rather than rounding every card independently. The layout remeasures as writing grows and when the editor is resized. Click empty Tree canvas to deselect and leave writing mode without collapsing the visible branch. An arrow key reselects the last card; Enter reopens it for writing. The Tree focus editor fills the entire window with a centered, borderless writing column, quiet chapter/cell context, and a small exit control. Desktop cell-type controls appear on hover or keyboard focus. Long writing scrolls inside this fullscreen view. The keyboard button lists the Tree shortcuts. With a card selected, **Enter** edits it, **Shift Enter** opens the fullscreen editor, and the arrow keys select siblings, a parent, or a child. **⌘/Ctrl Right** adds a child; **⌘/Ctrl Up/Down** adds a sibling above/below. **Alt Up/Down** reorders a branch, **Alt Right** nests it beneath the previous sibling, and **Alt Left** moves it outward. Moves carry descendants. **⌘/Ctrl Backspace** deletes the selected branch. **⌘/Ctrl Shift Up/Down** merges text notes into the previous/next sibling in reading order, keeping child notes. Patterns and ratings keep separate controls and cannot be merged into a text note. Delete, move, add, and merge operations offer one-step **Undo** in the current Tree session. Further text edits finish that undo step, so restoring structure cannot overwrite newer writing. The ⌘/Ctrl and Alt card commands also work while writing a Tree note, including in fullscreen. Plain Enter inserts a line break. While editing, plain arrows move the caret; at the beginning/end of a note, Left/Right selects its parent/first child, and Up/Down on its first/last visual line selects the previous/next sibling. These boundaries apply to the whole note, so moving between paragraphs stays inside the editor. Shift arrows keep selecting text. In Vim Normal mode, plain arrows navigate cards from any cursor position. Fullscreen arrows always stay inside the editor. Shift Enter opens fullscreen from either card navigation or writing. **Escape** closes inline or fullscreen editing and returns focus to the selected card. Search, rating controls, and practice form fields keep their own editing keys.

## Connected situations

Switch between **List** and **Map** on the situations screen. Selecting a node previews its notebook and connections; **Open notebook** continues work in the same situation. **Break out a subproblem** creates a new situation and notebook linked to the current one. Create subproblems from the graph using the inspector or pull-out stem. The notebook’s map button saves current writing before opening the graph; it does not start a subproblem draft.

**Edit map** enables dragging and renaming problems and editing connections. A connection can mean **Part of**, **Has subproblem**, or **Related to**. The first two describe the same directed relationship from opposite ends. A subproblem can have several containing situations. Related connections are undirected. Remove a connection to separate situations without removing either notebook. Within the current map session, the last successful graph change can be undone; undoing the link created with a new subproblem leaves its new notebook available as a standalone situation. Refreshing the map clears undo and loads the latest relationship for review after a conflict.

Selecting a card reveals a **pull-out stem** ending in a plus. Drag it into empty map space to place a subproblem, or click it (Enter/Space on the keyboard) to choose a nearby empty position. Name the subproblem in the inline card and choose **Create subproblem** to save its position and parent connection together. Cancel or Escape removes the draft without creating a situation or connection. Dropping over an existing card or outside the map creates nothing. The stem works in both viewing and editing modes. Floating zoom controls provide zoom out, the current percentage, zoom in, and fit to map.

Drag the background to pan, use the zoom buttons, or fit the map. With a problem focused in editing mode, arrow keys move it; Shift moves farther. Initial positions follow containment depth, while manually saved positions take precedence. Search highlights matching nodes and brings a match into view. The canvas handles presentation and gestures separately from the situation editor and workspace persistence.

Connections and optional map positions are stored on existing situation records and round-trip through workspace backups and sync. No database schema migration is needed. Connection edits update affected records atomically and require the displayed endpoint revisions. They reject self links, duplicate pairs, missing targets, and containment cycles. Related connections may form networks. Deleting a situation removes its incoming connections while preserving other notebooks. Existing context editors and notebook saves preserve graph data.

## Storage and practices

The versioned notebook is an optional field on an existing `Situation`. This needs no IndexedDB schema migration. The workspace validates and projects its contents before writes and backup imports. Existing context-only editors preserve notebook data. Full workspace backups and the existing workspace sync include notebooks.

Writes are debounced and serialized using the situation's revision check. Returning to the situations list flushes pending edits first. Failed or conflicting writes keep the current notebook open and offer retry and a downloadable JSON copy. Navigation warns when work remains unsaved. A downloaded notebook copy is a readable recovery document; use the workspace backup screen for a complete restorable backup.

Source-backed library practices use the existing Rust/WASM Pattern Language runtime and shared interaction controls. Each selected practice pins its source and checkpoint. Confirmed responses become editable answer cells; a persisted response ledger prevents a deliberately deleted answer from returning on restore. Unfinished practice fields are saved separately from confirmed responses. Practices needing unsupported external capabilities remain at that step with an explanation; Bearings does not send notebook answers to a model provider.

## Development checks

From the repository root:

```sh
pnpm --filter @patternverse/workspace build
pnpm --filter @patternverse/workspace test
pnpm --filter @patternverse/web check
pnpm --filter @patternverse/web exec vitest run src/lib/bearings
pnpm --filter @patternverse/web exec playwright test --config playwright.bearings.config.ts
```

The dedicated browser configuration uses port 4185. It checks desktop and mobile workflows, live practice checkpoints and drafts, deletion and undo, merging back to a continuous notebook, graph connections and shared subproblems, and desktop dragging and concurrent map edits. Avoid running a production build or regenerating SvelteKit routes while browser tests use the development server, since those operations replace generated route metadata.
